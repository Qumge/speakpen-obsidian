# Obsidian 同步可靠性

用户于 2026-11-02 正式要求完成此前专项计划，随后合并并发布新客户端。

沿用现有只读 GET 和普通 Markdown。自动同步在 workspace ready 后立即检查，窗口 focus／document visibility 恢复合并补查，至少间隔 60 秒；后台不轮询，保留默认五分钟周期，关闭 Obsidian 不同步。手动操作不受 60 秒限制，所有入口共享串行锁，卸载撤销旧请求的后续写入资格。

复用 /api/v1/me 的稳定 data.id 绑定账号状态，换 token 立即冻结旧代际；同账号换 token 复用游标，不同账号隔离游标和追踪文件。历史无 owner 的状态首次全量核对，仅采用当前账号返回的匹配 ID，不迁移其他账号文件。已发起的文件系统写入无法原子撤销，完成后只记入原账号检查点，后续操作必须重新检查代际。

完整成功才更新 lastSyncTime；尝试、部分失败、用户编辑冲突、等待和失败分别显示，设置页手机同样可见。原始转写与摘要分开，summary_status 失败／等待时不把 message 原文叫摘要。不得自动下载音频、上传 vault、删除用户笔记或扩大隐私范围。

复用现有增量／哈希保护而非新增同步服务或更密集轮询；现有机制足够，新增服务会扩大权限和成本。验证用合成 notes 和隔离临时 vault，不访问个人 vault。桌面真实宿主与移动真实宿主分别记录，不把模拟事件当手机验收。
